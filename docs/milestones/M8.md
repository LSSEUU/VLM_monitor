# M8：校园安全运营产品化

状态：**进行中（2026-08-10）**。M8.0–M8.2 已完成；M0–M6 保持冻结。下一切片为 M8.3
独立持久化、乐观并发、本地 API 与仓库解引用 RBAC。

## 已完成切片：M8.0 拓扑与来源真实性契约

本切片只交付：

- `CAMPUS -> BUILDING -> FLOOR -> ROOM` 的完整、有序拓扑 authority；
- camera/sensor 运营源目录；
- live、预录视频模拟、live sensor、模拟 sensor 的闭合来源模式；
- 显著模拟 badge、时间基准、manifest 与生命安全资格边界；
- Pydantic 契约、JSON Schema 快照和 contract tests。

本切片不交付 API、SQLite migration、RBAC、案件迁移、传感器样本、通知、真实设备或 UI。
这些能力按 `docs/spec/labcourt-campus-operations-spec.md` 的 M8.1–M8.7 顺序实现。

## 已完成切片：M8.1 actor/capability 与运营案件状态契约

本切片只交付：

- `LEADER / SAFETY_OFFICER / STUDENT / OPERATIONS` 四角色的闭合 capability 矩阵；
- 校园、地点集合、本人三类 actor scope 与 active/versioned authority；
- 只能创建 `PENDING_VERIFICATION` 的自动化案件 create command；
- 核实、驳回、补证、返回核实、结案、学生申诉与申诉处理的闭合动作/状态/reason 矩阵；
- 显式人工确认、本人申诉、地点作用域、禁止直接纪律处分与派生字段防伪造；
- transition-bound audit intent、Pydantic 契约、JSON Schema 快照和 contract tests。

本切片仍不执行案件写入，不提供身份认证、数据库、API、Agent、通知或 UI。actor authority 在
M8.3 必须由持久化仓库解引用，不能直接信任客户端提交的 authority 文档。

## 已完成切片：M8.2 typed 传感器端口与默认离线模拟插件

本切片交付：

- 七类 sensor 的 strict boolean/整数定点 type-unit-value 矩阵；
- source/catalog/sequence/timebase/quality/raw byte hash/input authority/manifest 完整样本 authority；
- adapter capability、bounded poll request、稳定 sample inventory result 与确定性 cache/replay；
- 可回读并按 SHA-256 核验的模拟 raw JSON；
- 版本化 typed risk rule/policy 与只产生运营候选的 assessment；
- 默认 smoke inactive→active bundle，active 形成显著 `SIMULATED` 的 `EMERGENCY` 候选；
- 通用 sensor port、typed adapter failure 和无网络/GPU/墙钟依赖的默认离线 adapter。

本切片不持久化 source/sample/cache，不建立案件，不触发通知、声光或消防联动，也不提供 API/UI。
这些 side effect 与仓库 authority 解引用属于 M8.3 以后切片。

## M8.0 状态转换与 manifest 影响

没有业务状态转换；仅定义将来持久化的静态 authority。每个运营源必须绑定一个 M8 组件
`manifest_id`，但不修改 `RunManifest` 或任何 M0–M6 manifest 身份。

## M8.1 状态转换与 manifest 影响

M8.1 只定义 transition command 与 audit intent，不执行持久化状态转换。命令绑定源 Case 版本、源
authority hash、actor authority、supporting authorities 和 `command_manifest_id`；审计意图再绑定
`audit_manifest_id`。这些均为新增 M8 authority，不修改 `RunManifest` 或 M0–M6 Case/Appeal wire。

## M8.2 状态转换与 manifest 影响

没有持久化业务状态转换。poll result 只读取冻结 scenario 并生成内存 sample/raw/cache authority；risk
assessment 只建议是否建立待核实案件，不执行 create command。source、adapter capability、scenario、
risk policy 和 evaluator 均绑定独立 manifest/authority，不修改 `RunManifest`、M0 `SafetySignal` 或
M0–M6 Case wire。
