## M8.3b2 状态转换与 manifest 影响

`commit_poll_result` 不改变案件状态，只把一个 exact adapter result 从内存变成 durable cache。新 poll 在
同一 SQLite 事务写入 raw BLOB、sample receipts、cache receipt 与 links；任一 hash、目录、sequence、
manifest 或 link 冲突会整体回滚。receipt 绑定 source/adapter/catalog/raw-storage/cache/repository manifest，
不修改 `RunManifest`、M0 `SafetySignal` 或任何 M0–M6 manifest 身份。risk assessment 与自动建案仍是后续
显式 application workflow，持久化 sample 本身不产生处分、消防或生命安全联动。

## 已完成切片：M8.3c loopback API 与持久化 RBAC

本切片交付：

- bearer credential authority 只把 token SHA-256 映射为 `actor_id`，不包含 role/capability；credential
  catalog 使用完整、稳定、唯一 hash inventory，API 无 catalog 不得启动；
- authenticated principal 只绑定 credential/catalog/authentication manifest，授权仍必须读取 SQLite 当前
  actor authority；
- Case transition HTTP request 明确排除 actor authority、role 与 capability，只保留 source fence、动作、
  reason、supporting authority、appeal resolution 和显式人工确认；
- 请求固定 `direct_disciplinary_action_permitted=false`，computed identity 与 extra 字段均 fail closed；
- typed API error reason 不包含内部异常、数据库路径或 credential 内容。
- hashed bearer authenticator 只比较 token SHA-256，认证结果不携带 role/capability，且无明文 token
  日志、默认凭据或免认证路径；
- application service 每次请求从 SQLite 解引用最新 actor authority，并按领导、安全负责人、学生、
  运维四角色执行读取、重大事件、本人案件、传感器和案件动作边界；
- 标准库 HTTP adapter 固定绑定 `127.0.0.1`，要求显式 authenticator，拒绝非本地 Host、跨站写请求、
  无界/非 JSON 请求体和客户端嵌套 actor authority；
- topology/source、sensor poll、Case、Case audit 与显式 transition 六类最小 API；typed 401/403/404/409/
  500 响应不泄露内部异常；
- 领导无审批动作，学生只能提交本人申诉，安全负责人显式确认后才迁移案件；所有成功动作仍由
  append-only Case/audit 事务与 source fence 决定。

M8.3 完整阶段验收：聚焦 API/port 231 passed；schema/architecture/registry 23 passed；291 份 schema

## M8.3c 状态转换与 manifest 影响

GET 请求不改变状态。POST transition 先以 credential catalog 认证 actor ID，再读取当前持久化 actor
authority，构造不含客户端权限声明的 M8 transition command；只有 M8.1 闭合权限矩阵、source Case
version/hash/status fence 和显式人工确认全部通过时，才原子追加 Case vN+1 与 audit event。认证、越权、
停用 actor、无效请求、并发冲突或完整性失败均不改变 Case。credential/catalog/authentication、command、
Case、audit 与 repository manifest 分别保留；不修改 `RunManifest` 或任何 M0–M6 manifest 身份。

## 进行中切片：M8.4a 通知计划 authority

已完成首个 contract-first 子切片：

- privacy-safe target authority 只保存 actor/provider/external binding hash、channel、revision、active、
  inbound-response capability 和 manifest，不保存明文平台账号；
- 默认本地目标固定 `LOCAL_OFFLINE_FAKE` 与 `SIMULATED · LOCAL MESSAGE`，外部通道不能嫁接 fake provider；
- template authority 绑定版本、生效 UTC、内容文档 hash、purpose/channel inventory 和 manifest，并固定
  `ordinary_document_can_define_case_rule=false`；
- escalation policy 绑定 risk、有限响应秒数/投递次数、升级角色与人工发送确认策略，不能迁移 Case 或把
  责任升级给学生；
- notification plan 绑定 exact Case version/hash/status、target/template/policy、显式 UTC 与 manifest，
  初态固定 `PLANNED`；subject 消息只发本人，领导只接收 severe/emergency；
- plan 固定禁止直接纪律处分、Case transition 与 external delivery claim，idempotency key 使用内容寻址 ID。

本子切片不写 outbox、不发送消息、不接收回复，也不声称任何消息已真实送达。下一 contract-first 子切片
冻结 lifecycle transition、dispatch/raw receipt、reply 与 persistence commit authority，再实现隔离 SQLite。

## M8.0 状态转换与 manifest 影响

没有业务状态转换；仅定义将来持久化的静态 authority。每个运营源必须绑定一个 M8 组件
`manifest_id`，但不修改 `RunManifest` 或任何 M0–M6 manifest 身份。

## M8.1 状态转换与 manifest 影响

M8.1 只定义 transition command 与 audit intent，不执行持久化状态转换。命令绑定源 Case 版本、源
authority hash、actor authority、supporting authorities 和 `command_manifest_id`；审计意图再绑定
`audit_manifest_id`。这些均为新增 M8 authority，不修改 `RunManifest` 或 M0–M6 Case/Appeal wire。

## M8.2 状态转换与 manifest 影响

没有持久化业务状态转换。poll result 只读取冻结 scenario 并生成内存 sample/raw/cache authority；risk
assessment 只建议是否建立待核实案件，不执行 create command。source、adapter capability、scenario、
risk policy 和 evaluator 均绑定独立 manifest/authority，不修改 `RunManifest`、M0 `SafetySignal` 或
M0–M6 Case wire。

## M8.3a 状态转换与 manifest 影响

自动 create command 原子追加 Case v1 与 audit sequence 1，状态固定为 `PENDING_VERIFICATION`。
显式人工 transition 在一个 `BEGIN IMMEDIATE` 事务中解引用当前 actor authority、比较 source Case
version/document hash，并原子追加 Case vN+1 与同序号 audit event。并发失败、停用/换版 actor、越权、
断链或 manifest graft 均不改变 Case。actor receipt、Case authority、audit event 和 commit receipt 分别
绑定 authority/case/audit/repository manifest；不修改 `RunManifest` 或任何 M0–M6 manifest 身份。
