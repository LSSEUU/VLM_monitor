## 已完成切片：M8.2 typed 传感器端口与默认离线模拟插件

## M8.0 状态转换与 manifest 影响

没有业务状态转换；仅定义将来持久化的静态 authority。每个运营源必须绑定一个 M8 组件
`manifest_id`，但不修改 `RunManifest` 或任何 M0–M6 manifest 身份。

## M8.1 状态转换与 manifest 影响

M8.1 只定义 transition command 与 audit intent，不执行持久化状态转换。命令绑定源 Case 版本、源
authority hash、actor authority、supporting authorities 和 `command_manifest_id`；审计意图再绑定
`audit_manifest_id`。这些均为新增 M8 authority，不修改 `RunManifest` 或 M0–M6 Case/Appeal wire。

## M8.2 状态转换与 manifest 影响

没有持久化业务状态转换。poll result 只读取冻结 scenario 并生成内存 sample/raw/cache authority；risk
assessment 只建议是否建立待核实案件，不执行 create command。source、adapter capability、scenario、
risk policy 和 evaluator 均绑定独立 manifest/authority，不修改 `RunManifest`、M0 `SafetySignal` 或
M0–M6 Case wire。

## M8.3a 状态转换与 manifest 影响

自动 create command 原子追加 Case v1 与 audit sequence 1，状态固定为 `PENDING_VERIFICATION`。
显式人工 transition 在一个 `BEGIN IMMEDIATE` 事务中解引用当前 actor authority、比较 source Case
version/document hash，并原子追加 Case vN+1 与同序号 audit event。并发失败、停用/换版 actor、越权、
断链或 manifest graft 均不改变 Case。actor receipt、Case authority、audit event 和 commit receipt 分别
绑定 authority/case/audit/repository manifest；不修改 `RunManifest` 或任何 M0–M6 manifest 身份。
