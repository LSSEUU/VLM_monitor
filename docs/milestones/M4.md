# M4：三角色会审与受限主动取证

状态：**完成并冻结（2026-08-02）**。M0–M4 均已冻结；后续生产判例、告警、申诉与训练标签
副作用只在 M5 的新增契约和事务边界中实现。

## 目标与边界

M4 交付从 `ESCALATED | REWORK_REQUIRED` 到通过程序审查、明确重审、积压或转人工的完整
纵向切片：

```text
ESCALATED | REWORK_REQUIRED
-> DELIBERATING
-> precedent context
-> Prosecutor
-> Defender
-> Judge
   -> one typed acquisition -> EvidencePack v+1 -> next cycle
   -> proposed Verdict -> L5
      -> pass -> READY_FOR_ALERT_POLICY
      -> fail -> bounded rework or HUMAN_REVIEW
```

本阶段不实现生产判例库、告警 outbox、申诉、训练导出、回归报告或 HTML
演示站点；这些分别属于 M5 和 M6。判例检索只使用可替换的受控 fake，并
显式记录降级。

## 冻结规则

- M3 的 `Case`、`EvidencePack`、`Verdict`、初审请求/响应/解析合同、枚举和
  已导出的 schema 不修改。
- M4 使用独立的 hearing root、模型调用合同、SQLite repository、worker
  和 projection/readonly validator。
- 总 Judge 次数为 `1 + acquisition(≤2) + rework(≤2) ≤ 5`；两个预算相加，
  不嵌套相乘。
- provider/严格解析失败进入精确角色的 `HEARING` backlog，不替换角色，
  不从头重跑已持久化步骤。
- 每个角色 primary response 最多允许一次无媒体 structure repair；repair
  不增加逻辑 Judge cycle，但消耗累计 token、成本与调用计数。两次严格解析
  均失败才进入 exact-role backlog；新的严格解析 generation 从同一角色
  primary 重新开始，provider 中断或 crash 则恢复尚未完成的 exact call。
- 每轮最多一个取证动作。参数仅为五种 discriminated typed model，禁止
  路径、SQL、shell、URI 或任意命令字段。
- 补证产生严格的 `EvidencePack v+1`，保持既有证据不变；取证 request、
  validated parameters、result refs 和执行 manifest 全部可追溯。
- `OTHER_CAMERA_SAME_TIME` 在现有 EvidencePack 下仅提供 metadata：外机位
  FrameRef 可进入 ToolResult closure，但不得进入 key frames/crops/role
  media 或支撑视觉结论；不做人脸识别或跨相机 ReID。
- 未回应任何一条辩点都会由 L5 产生
  `UNANSWERED_DEFENSE_POINT`；允许重审最多两轮，随后转人工。
- raw response 先落盘、后解析；维护恢复无 provider、无解析、无工具执行、
  无案件推进权限。
- 每次补证先取得带 owner digest、lease 和单调 fence 的 typed execution claim，再把
  request、execution manifest、ToolResult 和全部 typed outputs 发布为不可变 execution
  publication；EvidencePack 的修改必须使用这份已完成 publication。
- `PURE` 工具的过期 claim 可由更高 fence 接管；`IDEMPOTENT_EXTERNAL` 的未知外部投递
  必须先恢复，无法证明结果时只能持久化为 `ABANDONED`，不得盲目重打工具。
- 每条 `EvidencePack v -> v+1` 另有相邻 derivation 记录，精确绑定 request、publication、
  execution manifest、ToolResult、receipt、前驱/后继 pack 和 Case revision；不能跨 run、
  跳版本、换前驱或分叉。
- 已证明 `DEFINITELY_NOT_SENT` 的 provider 重试失败建立 exact lease-generation call 的
  `RETRY_FAILURE` model-call authority；严格解析失败另由 response、strict proof、typed
  outcome 和 completion receipt 闭包，不伪装成 provider failure。过期 worker lease 仅以
  `WORKER_LEASE_EXPIRED` 绑定原始 backlog stage input，既无 response refs，也无
  model-failure authority。

## 实现切片

1. M4 root contracts、三份独立 prompt、严格 schema 和 golden identities。
2. 独立 hearing request/response/cache/parser 与三角色 fake。
3. 五种确定性 acquisition executor、执行闭包和 EvidencePack 版本化。
4. 有界 coordinator、Verdict builder、L5 rework/human transition。
5. SQLite migration `0008_m4_hearing_and_acquisition.sql`、事务、reload 和
   read-only 双向校验。
6. hearing backlog retry、provider-free recovery、CLI 与离线 E2E。
7. public M4 artifact report、successor-aware M2/M3 缺陷翻译、物理 PNG 复验和 current
   projection 全量对账。

以上实现均已落地，并通过本文件末尾记录的冻结门禁。

## 公开验收入口

推进一个明确 Case：

```bash
labcourt hearing process \
  --run-id <run_id> \
  --case-id <case_id> \
  --fixture-bundle <m4-fake-vlm-fixtures.json>
```

回收过期 lease，并最多处理一个 exact-role hearing backlog item：

```bash
labcourt hearing backlog retry \
  --run-id <run_id> \
  --worker-id <stable_worker_id> \
  --fixture-bundle <m4-fake-vlm-fixtures.json>
```

只收敛已精确落盘的 response journal：

```bash
labcourt hearing recover-responses --run-id <run_id> --limit 10000
```

校验 M4 SQLite 权威、物理媒体和 current projection，且不写入工作区：

```bash
labcourt artifacts validate --run-id <run_id>
```

`hearing process` 与 `hearing backlog retry` 的 fixture bundle 使用
`m4-fake-vlm-fixture-bundle-v1`。`fixtures` 逐项绑定三角色的精确 request；可选
`acquisition_fixtures` 最多 64 项，逐项携带完整 `AcquisitionRequest` 和动作允许的 typed
outputs，按 request ID 唯一稳定排序。`acquisition_fixture_count` 同时进入 bundle 身份和命令
报告，不是日志推算值。

只要存在 authored acquisition fixture，RunManifest 的 `software_components` 必须精确包含
`m4-controlled-fake-acquisition -> {package=labcourt, version=0.1.0,
license_id=Proprietary}`。工具 manifest 使用该 canonical 组件文档字节的 SHA-256；未 pin 或
内容漂移在任何 M4 补证权威创建前返回 `ACQUISITION_COMPONENT_UNPINNED`。

这些入口均为离线验证面。进程与 backlog 输出显式标记
`SIMULATED PERCEPTION / FAKE VLM / CONTROLLED FAKE`；response recovery 标记
`NO PROVIDER / RECOVERY ONLY`。fixture、报告计数或门禁结果均不得解释为真实场景准确率、成本、
延迟或吞吐数据。

## 只读工件判定

存在 M4 权威时，公开 validator 从一个私有 SQLite 快照重建 M4 root，双向验证 audit、Case
head、hearing/checkpoint/round、role call、raw response、backlog completion、补证 claim/
publication、相邻 pack derivation、Verdict binding 与 current pack。所有 EvidencePack crop 和
独立 acquired crop 都重新走物理 PNG 校验；随后逐项核对内容寻址的 M4 projection generation。

M4 后继会使冻结 M2/M3 validator 观察到少量预期差异。只有在 M4 authority 与媒体均通过时，
validator 才会 supersede 三类已被精确证明的旧 finding：M2 current pointer 已由 M4 projection
接管、M4 明确引用的 raw response 被旧 M3 视为 unreferenced、M4 hearing Verdict 使用新增 binding
而被旧 M3 视为不匹配。其余 M2/M3 issue 全部翻译为 `EMBEDDED_M3_DEFECT` 并继续 gating；不会因
进入 M4 而掩盖历史损坏。

## 必测场景

- 三个角色由不同 fake/profile 驱动，且顺序与作用域不可伪造。
- M3 fast-verdict L5 失败可作为 M4 cycle 1 的初始上下文，并不消耗 M4
  的两次 rework 预算。
- 检察官引用未知证据、辩护人引用未知证据、法官引用未知判例均 fail
  closed。
- 法官漏回一条辩点：L5 失败、进入重审；连续三份失败提案后转人工。
- 两轮取证后仍请求取证：不执行第三个工具、不建新 pack、不再询问 Judge，
  直接 `ACQUISITION_LIMIT_EXHAUSTED -> HUMAN_REVIEW`。只有当前输出本身已
  是 terminal 且明确 `INSUFFICIENT_EVIDENCE`，才照常构造 Verdict/L5。
- 五种工具参数和 input/output 矩阵；路径/命令注入被合同拒绝。
- Case 的 pack 历史保持前缀；新 pack 是旧 pack 的语义超集，旧对象逐个
  完全相等且仍存在，内部稳定排序 tuple 不要求字面前缀；closure 与 latest
  Case/EvidencePack binding 精确，并发换包整体回滚。
- prosecutor/defender/judge 各自 outage、malformed、cache hit/tamper、
  过期 lease 与精确 checkpoint 恢复。
- primary malformed + repair valid 在同 cycle 成功；primary/repair 都
  malformed 时进入 exact-role backlog 并仅为该角色开启下一 generation；
  primary 已持久化后 crash 则从 repair 恢复且不重打 primary；repair
  无媒体、计入累计 token、不增加 Judge cycle。
- embedding/判例上下文失败显式 degraded，但不伪造判例、不替换角色。
- crash 在 raw publish、role commit、tool execution 和 pack publication
  各边界均可恢复或安全转人工，不重复 provider/tool 副作用。
- SQLite reload、projection rebuild 与 readonly artifact validation 得到
  相同 hearing/pack/verdict/review 根。
- foreign-camera FrameRef 只能进入 ToolResult closure；若进入 key frames、
  crop、role media 或被 Judge 直接作为视觉证据则 fail closed。
- `DELIBERATING | REWORK_REQUIRED | BACKLOGGED -> HUMAN_REVIEW` 的六种
  hearing reason 都必须有 exact `HearingHumanReviewReceipt`；伪造 receipt、
  reason、cycle、current pack 或 backlog completion 时 reload fail closed。
