# M3：语义初审与确定性程序审查

状态：**已完成并冻结（2026-07-28）**。M0–M3 全部门禁通过；下一阶段为 M4
三角色会审与受限主动取证。

## 冻结交付摘要

- 受控模型调用具备 request singleflight、owner/lease compare-and-swap、Fake 与
  OpenAI-compatible contract suite、原始响应先落盘、cache 重验和最多一次纯结构修复。
- provider 失败只有在 `DEFINITELY_NOT_SENT` 或已完成时才可形成后续业务重试权威；未知投递与
  过期 claim 必须先走 provider-free maintenance recovery，不会静默重复调用。
- backlog 的每次 lease 都消耗一次尝试；退出 lease 必须有精确 completion receipt。SQLite v7
  trigger 与只读重建双重验证相邻历史，禁止 `LEASED -> LEASED` owner takeover。
- FastVerdict 与 L5 十四类缺陷均为确定性实现；L5 不看像素、不修写 verdict，通过只表示可进入
  后续 alert policy。
- JSON 投影使用不可变、内容寻址 generation；`current.json` 是唯一原子提交点。pointer、
  manifest、正文和双向目录 inventory 均与只读 SQLite authority 重建结果逐字节核对。
- `labcourt artifacts validate` 只校验最终 SQLite/media/raw/current generation 权威；
  publication journal 与 staging 是 `labcourt maintenance recover` 的运维输入，不冒充正式工件。
- 大型实现已按模型调用、aggregate、backlog、SQLite foundation/model/decision/backlog、
  readonly codec/relation 等责任拆分；冻结接口不要求后续 M4 继续膨胀 M3 模块。

冻结决策记录为 ADR 0010、0011、0012、0013；对应迁移为
`0004_screening_and_gate.sql`、`0005_backlog_completion_receipts.sql`、
`0006_model_call_failure_authority.sql` 与 `0007_m3_authority_hardening.sql`。

## 目标与边界

M3 交付从 `EVIDENCE_READY` 案件到“可快审裁决或明确升级”的完整纵向切片：

```text
EvidencePack current closure
-> 受控 VLM 请求
-> 原始响应安全落盘与缓存
-> 严格解析（最多一次仅结构修复）
-> presence/absence screening 路由
-> FastVerdictBuilder
-> L5 十四类确定性程序缺陷
-> SQLite 事务、audit、projection、reload verification
```

本里程碑不实现 L4 三角色会审、主动取证、判例检索、告警 outbox、申诉或训练导出。需要 L4
才能解决的案件进入 `ESCALATED`；provider 不可用、预算耗尽或两次输出均无效时进入 typed
backlog/人工路径。任何 VLM 失败都不得影响已认证硬安全信号。

权威依据为规格第 11、13、16.3、18、19 节以及 ADR 0002、0003、0005、0007、0008。M3
开始前新增 ADR，冻结模型响应、缓存、快审状态和程序审查的事务语义。

## 承重决策

1. **解析失败不是 Verdict。** 原始 JSON、结构解析结果和程序审查结果分层保存。Pydantic
   对象构造失败时，以 typed parse defect 进入一次结构修复；不得用宽松解析器猜字段或枚举。
2. **未知引用永不自动纠正。** adapter 在进入业务 contract 前记录所有不在请求白名单中的
   crop/frame/precedent ID；L5 产生 `FABRICATED_*_REFERENCE`。
3. **源响应与公开工件分离。** 原始响应只保存到
   `<workspace>/<run_id>/model_responses/<response_id>.json`，目录和文件 owner-only，公开
   verdict 只引用 response ID、相对 locator 和内容 hash，不内嵌任意 provider JSON。
4. **缓存命中仍重验。** cache key 包含 provider/model/revision、prompt/output schema hash、
   有序媒体 hash、隐私变换版本、规范文本输入与解码参数。命中后仍验证响应 hash、请求绑定、
   白名单和输出 contract。
5. **L5 不看像素。** 它只消费当前 pack、结构化模型标签、客观事实、规则配置和受控 lookup；
   它拦截幻觉与流程缺陷，不宣称提高语义准确率。
6. **快审不是绕过审查。** `FastVerdictBuilder` 生成完整 `Verdict`，随后必须通过同一个 L5。
   M3 不发送告警；通过仅表示案件具备进入后续 alert policy 的资格。
7. **单一状态权威。** screening、verdict、procedural defects、model cache、backlog、case
   revision 与 audit 在 SQLite 明确事务边界中提交；JSON/JSONL 仍是提交后可重建投影。

## 实现顺序

### 1. Contract 与 schema

- 为请求、响应、解析 receipt、screening、verdict、procedural review 补齐 `run_id`、版本、
  manifest、内容 hash、预算和稳定身份。
- `ProceduralReview.passed` 由 defects 计算并拒绝伪造 serialized 值。
- 固定十四个 `ProceduralDefectCode`，每个缺陷的必要上下文字段受 contract 约束；公开详情
  只能是受控 reason code/typed refs，不能包含 provider 原始异常或主机路径。
- Prompt manifest 固定 prompt ID、UTF-8 bytes hash、output schema hash 和角色。
- 所有新增根 contract 注册 JSON Schema，并增加 Python/Schema 一致性与 golden identity。

### 2. Prompt、响应存储、缓存与 provider

- prompt 文件独立存放，StrictUndefined 渲染；用户/规则文本以 canonical JSON 数据嵌入。
- `DeterministicFakeVLMClient` 是默认 provider，按 request/cache key 选择显式 fixture，禁止
  网络和隐藏全局状态。
- OpenAI-compatible adapter 通过注入的 transport 做 contract/integration 测试；真实 endpoint
  与 API key 只从配置指定的环境变量读取，日志、异常、fixture 不得包含 secret。
- 外部请求构造器只读取 `CLOUD_ALLOWED`、非 panorama 的已验证媒体；本地 profile 才可使用
  `LOCAL_ONLY`。任何 bytes/hash/identity 变化在发送前失败。
- 原始响应 store 使用 SecureWorkspace 两阶段发布、0600/owner-only 权限和内容 hash。
- SQLite cache 以 cache key 唯一；相同 key 不同响应 hash 为 integrity failure。

### 3. 严格解析与 screening

- 首次响应仅接受单个 JSON object，限制总 bytes、嵌套深度、字段数和字符串长度。
- 首次 contract 失败只允许一次 `STRUCTURE_REPAIR` 请求；修复请求绑定原 request、原 response
  hash 和受控错误码，不增加媒体或证据。
- 第二次失败转换为 `ModelOutputInvalid` 并落入 backlog；不得产生半合法 `ScreeningResult`。
- presence 路由按 low/high 阈值和强信号冲突执行。
- absence 路由只聚合涉嫌区间内、达到清晰阈值的逐 crop `WORN/NOT_WORN/UNCLEAR` 标签；纠正帧
  只形成上下文，不反写涉嫌区间。
- 路由是纯函数，稳定输入必须产生逐字节一致输出。

### 4. FastVerdictBuilder 与 L5

- 快审成立必须有 evidence、控方论点和一致的违规类型；不成立也保留支持它的结构化引用。
- 不伪造辩方、法官、判例或主动取证记录。
- L5 依次产生并稳定排序十四类 defect；不得因前一个 defect 短路而隐藏其他独立问题。
- 证据存在性、case/run/pack scope、media current closure、客观事实、辩点集合和缺失型观测
  充分性均通过 typed ports/纯领域数据验证。
- 同一 defect 输入幂等；程序审查器绝不修改 Verdict。

### 5. SQLite 与纵向 E2E

- `0004_screening_and_gate.sql` 创建受约束的 model response/cache、screening、verdict、
  procedural defect 和 backlog 表；append-only 实体由 trigger 拒绝更新/删除。
- 同一 request/cache/result/verdict 重试幂等，不重复 case revision 或 audit。
- current pack 在调用前和提交事务内均重验；revision/head 冲突整体回滚。
- E2E 覆盖：
  - presence 低/高/灰区；
  - absence 存在清晰 WORN、足量 NOT_WORN、全 UNCLEAR；
  - unknown crop ref；
  - 客观人数/时长矛盾；
  - 两次 malformed response；
  - provider outage/backlog；
  - cache hit 与 cache tamper；
  - SQLite reload 后相同 L5 结果。

## 十四缺陷验收矩阵

每个枚举至少一个独立单测；以下集合另加 property-based tests：

| 缺陷码 | 核心触发 |
|---|---|
| `MALFORMED_STRUCTURE` | 根 JSON/对象结构不可解析 |
| `INVALID_ENUM` | 未知或大小写伪造的枚举值 |
| `MISSING_REQUIRED_FIELD` | 必填字段缺失且结构修复仍失败 |
| `FABRICATED_EVIDENCE_REFERENCE` | 引用不在当前 pack 白名单 |
| `INVALID_COORDINATES` | 结构化坐标越界或与引用不一致 |
| `FABRICATED_PRECEDENT_REFERENCE` | precedent lookup 不存在/不可见 |
| `PRECEDENT_DIRECTION_MISMATCH` | `FOLLOWED` 与裁决方向冲突 |
| `EMPTY_DISTINGUISHING_REASON` | `DISTINGUISHED` 无理由或事实差异引用 |
| `ESTABLISHED_WITHOUT_EVIDENCE` | 成立但无 evidence/控方论点 |
| `UNANSWERED_DEFENSE_POINT` | defense ID 与 JudgeResponse 非一一对应 |
| `CONFIDENCE_ALERT_LEVEL_MISMATCH` | 置信度/证据不足却建议高等级 |
| `OBJECTIVE_ASSERTION_CONTRADICTION` | 客观 claim 超出配置容差 |
| `VIOLATION_TYPE_MISMATCH` | Verdict 与 Case/Event 类型不一致 |
| `ABSENCE_FROM_INSUFFICIENT_OBSERVATION` | 缺失型成立但清晰帧不足、含 WORN 或非全 NOT_WORN |

M3 不构造真实 precedent，因此快审 verdict 的 precedent applications 必须为空。判例相关三类
缺陷使用受控 lookup fake 完整实现和测试，生产存储到 M5 接入；不得用永远返回空的 stub
宣称已完成分支。
