## 冻结运维界面

### 只读工件校验

```bash
labcourt artifacts validate --run-id <run_id>
```

该命令对指定 run 校验 audit chain/head、SQLite canonical documents、current closure、
`current.json` 所指向的完整 projection generation，以及当前媒体的文件、尺寸、PNG 与 hash。
它不把旧固定布局或未被 current 引用的 generation 当作当前投影；也只验证已持久化的
current media，不声称可以重放已不存在的 source pixels 或隐私变换。

在物化任何大型文档前，校验器对数据库总字节、单个 canonical document 字节、audit entries、
events、cases、packs、media 和 projection 字节执行有界预检。主数据库与已存在的 WAL/SHM
被当作同一个源集合：从已安全打开的只读 handle 流式复制到 owner-only 临时目录，前后复核
存在集、identity、时间、尺寸与 hash，然后只把私有副本交给 SQLite。因此校验不会故意修改
权威 main/WAL/SHM；源集合在复制中变化时 fail closed。

预检得到的 audit/event/case/pack/media 权威计数会继续绑定到最终报告，并与验证器实际遍历的
闭包集合逐类对账。任何多余或缺失的库存行都会产生 typed
`AUTHORITY_INVENTORY_MISMATCH`，因此未进入 Case/Pack 闭包的孤立 pack 或 media 不能借由
“未被遍历”获得通过。

退出码是稳定接口：

- `0`：校验完成，`report.passed=true`；
- `1`：校验完成但报告包含完整性、闭包、audit、projection 或有界计数/文档预算问题；
- `2`：配置或预算无效、源数据库总字节超限、数据库/run 不存在，或快照/路径/repository
  边界无法建立可信报告。

### 有界启动恢复

```bash
labcourt maintenance recover --run-id <run_id>
```

命令在任何 quarantine、unlink 或其他恢复性 workspace 变更前验证已存在的数据库与 run，
然后由
`StartupRecoveryCoordinator` 以不可调换的顺序执行：

1. 先恢复 retention/PURGING，完成未结束的状态转换与 `.trash` 清理，无法完成时返回
   `RECOVERY_REQUIRED`；
2. retention 成功返回后才扫描当前 run 的 `.staging` 和内容寻址 `frames`；
3. 经证实未被 SQLite 引用且超过最小年龄的候选被移入受控 `.quarantine`，不递归删除；
4. 对已超过最小年龄、精确匹配 `.staging/<run>/<operation>` 形状且经验证为空的操作目录，
   只执行该目录的非递归删除；年龄未到时保留并返回 `MINIMUM_AGE_NOT_MET`。

扫描对 staging 与 final media 分别使用有界预算，避免一个区域的毒丸或满额前缀长期饿死另一区域。
未知形状、路径边界违例或恢复未完成都保留 typed 结果，不被异常吞掉。

退出码同样是稳定接口：

- `0`：恢复报告完成且无 `RECOVERY_REQUIRED`/异常；年龄未到的受控保留不单独导致失败；
- `1`：恢复报告完成，但 retention 结果需人工关注或 orphan 报告含 typed anomaly；
- `2`：配置、数据库/run、参数或安全边界阻止执行或阻止产生可信报告。

### SQLite writer 与删除边界

可写主库固定为 `labcourt.sqlite3`。普通 repository 只以 `mode=rw` 打开已存在数据库，缺失时
fail closed；只有 migration runner 能使用 owner-only、exclusive-create 原语首次创建。writer 在连接前、
PRAGMA 完成后和关闭前复核父目录、主库与 WAL/SHM 的路径、identity、regular/single-link 等不变式；
遇到 rollback journal 直接拒绝，不猜测恢复。

但标准库 SQLite 仍通过路径打开主库与 sidecar，这不是 custom VFS。检查前后的 identity/hash
复核可以阻断或发现普通替换，但不能排除同权限攻击者在检查间完成完美 ABA。完全消除需要
custom VFS、操作系统快照或更强的权限隔离，不属于 M2。retention 最后从文件系统 unlink 已验证的
trash 文件，只能声称该路径不再可达；由于 SSD wear leveling、TRIM、文件系统/设备缓存与备份，
它不等于可证明的物理数据擦除。

## 范围

M2 交付以下可验证纵向切片：

- OpenCV 本地 CFR 视频适配器，作为 lazy、headless 的可选 `video` extra；
- 默认 CPU、无 GPU、无网络的 RGB8 裁切与确定性 PNG adapter；
- trigger 前后时间窗、状态突变、首尾、恢复帧和缺失型 top-M 关键帧选择；
- panorama、subject、presence focus、absence anchor focus 与 recrop 几何计划；
- PPE 保真遮蔽、full redaction、ephemeral raw TTL 和 typed privacy receipt；
- 创建时 EvidencePack closure 与使用前 current availability/closure；
- SQLite 版本迁移、case/pack/media 持久化与乐观并发；
- events/audit JSONL、case/pack JSON 的原子可重建投影；
- 逐 run audit hash chain；
- retention hold、合法像素清除、启动恢复和 orphan 隔离；
- 从 M1 CandidateEvent 到 `EVIDENCE_READY` Case 的离线 E2E。

M2 不实现 L3 语义初审、L4 会审、L5 程序裁决、alert/outbox 发送、判例、申诉业务、真实
VLM/检测模型、RTSP、VFR、多摄像头时间同步、生产身份或远端审计锚定。M2 可以创建这些
未来层需要的稳定端口，但不得用空业务实现宣称完成后续里程碑。

## 契约与状态

M2 的必需 contract 变更先于行为代码和迁移：

1. `FrameSource.get_range` 显式加入 `stream_id`；运行时像素通过只读 RGB8 类型提供，
   `FrameRef.content_sha256` 在实际解码后必填。
2. `CropRequest` 携带 privacy 所需关键点/anchor、来源引用、track、observability 和版本；禁止
   用开放字符串 tags 传递权威隐私参数；请求同时携带已验证的输出宽高，panorama 还携带
   long-edge limit，使缩放计划可由 FrameStore 重验并进入 crop 身份。
3. `Crop` 区分 source pixel、output pixel 与 PNG file hash，并保存输出尺寸、媒体类型、
   privacy receipt 和可墓碑化的相对 locator。
4. objective/tool 引用改为带 kind 的 typed artifact reference。
5. `ClosureReport.passed` 由 typed defects 计算；持久化层不信任调用方提供的 passed 值。
6. 新增 AuditEntry、ArtifactVerification、RetentionHold、PurgeItemResult、StreamManifest 和
   run/case 复合引用 contract。
7. RunManifest 记录 input file hash、decoder/backend/codec、权威 FPS、RGB/hash/encoder 版本与
   Pillow/OpenCV software component；每个视频流还必须显式记录 `timing_mode=CFR` 及其
   `timing_authority`，OpenCV 的浮点 FPS 只用于一致性核验。

这些新增必填字段和 port 参数属于破坏性 wire/API 变化，公共 schema 版本升为 `2.0.0`，同步
更新生成 schema、fixtures、golden hashes 与迁移读取器；不得让旧 `1.0.0` 工件被默认为已
完成 M2 物理校验。

案件状态转换为：

```text
CandidateEvent 首次持久化 -> CANDIDATE
闭包通过但后窗未齐的 pack v1 -> 仍为 CANDIDATE
闭包通过且 complete=true 的最新 pack -> EVIDENCE_READY
证据缺失、hash 损坏或隐私策略无法满足 -> HUMAN_REVIEW，并保留 typed failure audit
SQLite revision/head 冲突 -> 整体回滚并返回 ConcurrentModification，不改变案件状态
```

无效 pack 不进入 `evidence_packs`。合法 retention 后，创建时 closure 历史仍有效，但当前
closure 返回 `PURGED_BY_RETENTION`；需要像素的新推理不得继续。

## 分层与依赖顺序

按以下顺序实现；同一编号内可并行，后项不得绕过前项：

1. ADR、Pydantic contracts、JSON Schema、golden vectors 和 port contract tests。
2. 纯 domain：时间窗、稳定关键帧排序、bbox 扩张/裁边、panorama 尺寸和语义引用闭包。
3. 可并行的 adapter 基础：
   - SecureWorkspace、RGB8/Pillow FrameStore 与 privacy transforms；
   - SQLite migration runner、repository/UoW、audit chain 与 JSONL projector；
   - lazy OpenCV video adapter、fake backend contract test 与可选真实视频 smoke test。
4. application `build_evidence` 与两阶段 publish，包含 pack input 幂等和 case revision。
5. retention/purge、staging/orphan/PURGING 启动恢复和 artifact validator CLI。
6. M1 event 到 M2 pack、SQLite、投影、重载 closure 的 E2E，再运行全部质量门。

建议职责边界：

```text
contracts -> domain -> application -> ports <- adapters

domain:      evidence_window / crop_geometry / semantic_closure / audit_hash
application: build_evidence / publish_evidence / project_artifacts / retention
adapters:    frame/opencv_video / media/pillow_frame_store /
             storage/secure_workspace / storage/sqlite / storage/jsonl_projector
```

`domain` 不接触路径、文件、数据库或图像库；`application` 不 import `cv2`、Pillow 或
`sqlite3`。物理 closure 通过 ports 获取 typed verification，不把 adapter 异常吞成 bool。

## EvidencePack 闭包

发布前验证器至少检查：

- trigger、key frame、crop、objective source 和 tool 输入输出均存在；
- 所有 frame/crop 属于当前 run、camera、stream、案件区间和主体；
- bbox 位于源帧边界，crop role 与 `CropSource` 匹配；
- temporal crop 位于涉嫌区间、属于 primary track 且带 observability；
- absence clear/unclear 集互斥且只引用当前 temporal crops；
- event objective facts 未被 pack 改写，新增事实有真实来源；
- 相对路径安全，实体为单链接 regular file，尺寸、PNG、输出尺寸和三个媒体 hash 一致；
- privacy receipt、媒体 access、关键点/anchor 与用途相容；
- `EPHEMERAL_RAW` 不在 pack，panorama 与 privacy fallback 均为 `LOCAL_ONLY`；
- event、case、pack 与 manifest 引用一致，显式 semantic projection 重算出相同 `pack_id`。

`complete=false` 表示实时 post-window 未齐；它包含的所有现有引用仍必须通过 closure。后窗
收齐后生成更高版本且不覆盖旧版本。关键帧去重和排序使用固定优先级，并在 observability
同分时按 `frame_index`、`frame_id` 排序。

## SQLite 与投影

M2 迁移的最小表及关键约束见 ADR 0005。所有连接开启并核验 WAL、foreign keys、FULL
synchronous、固定 busy timeout 与 trusted schema off。case/pack/media/audit 在一个
`BEGIN IMMEDIATE` 事务中提交；文件先按 ADR 0008 安全发布，数据库后提交。JSONL/JSON 在
提交后从 DB 重建，不做 DB 与正式 JSONL 双写。整代发布和单调 current 切换遵循 ADR 0012。

可信投影位于
`<run_id>/projections/generations/<generation_id>/`，由
`<run_id>/projections/current.json` 选择；代内格式：

- `events.jsonl`：按创建 audit sequence 排序，每行一个完整 CandidateEvent canonical JSON；
- `audit.jsonl`：按 sequence 排序，每行一个 LCJ-AUDIT-1 stored entry；
- `cases/<case_id>.json`：当前 Case canonical JSON；
- `packs/<pack_id>.json`：EvidencePack canonical JSON，locator 从 `media_assets` 物化；
- 所有文本使用 UTF-8、无 BOM、LF；JSONL 最后一行也以 LF 结束。

| P0 | SQLite 状态写入中途失败 | case、pack、media、audit 全部回滚 | integration |
| P0 | audit payload、prev 或顺序篡改 | verifier 返回首个断链 sequence | unit/integration |

M2 的纵向 E2E 固定为：

```text
M1 CandidateEvent
-> 关键帧选择
-> 隐私裁切与媒体 hash
-> creation closure
-> 文件发布
-> SQLite case/pack/audit 事务
-> events/audit JSONL 与 case/pack JSON 投影
-> 重载并验证 current closure
-> 篡改一个 PNG 后以 typed integrity failure 结束
```

## 质量门与完成条件

```text
mingw32-make format-check
mingw32-make lint
mingw32-make typecheck
mingw32-make test
mingw32-make e2e
mingw32-make schemas-check
```

Linux/macOS 可使用 `make`。默认质量门不安装 OpenCV、不访问网络、不需要 GPU。OpenCV
extra 另有安装 `video` extra 的平台 smoke job；核心 adapter 行为仍由默认 fake backend
contract tests 覆盖，不能因 optional dependency 缺失而全部 skip。

里程碑完成还要求：

- M2 contract/schema 生成后工作区无差异；
- domain/application 依赖边界测试通过；
- migration schema、index、FK、trigger 和 PRAGMA 有快照/行为测试；
- LCPIX1、crop/pack identity 与 LCJ-AUDIT-1 有跨实现 golden vectors；
- Windows junction/reparse 与 POSIX symlink 测试至少在对应平台门中真实执行；
- fixture 只有程序生成图形，不包含真实人员图像或密钥；
- 每个提交说明 contract、状态转换、场景覆盖和 RunManifest 影响。

## 非性能与非能力声明

M2 的合成 fixture 只能证明契约、文件完整性、隐私像素规则、事务和恢复行为，不能证明真实
实验室中的 PPE 识别准确率、匿名化效果、视频吞吐、端到端延迟、存储成本、断电耐久性或
法律合规。没有真实评测工件时，README、报告、提交和演示均不得声称这些指标已经达标。
