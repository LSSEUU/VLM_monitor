## 目标与边界

M5 交付从 `READY_FOR_ALERT_POLICY` 到可申诉终局的完整确定性闭环：

```text
READY_FOR_ALERT_POLICY
-> deterministic alert policy
-> CLOSED + alert outbox                 (one SQLite transaction)
-> provisional/active precedent + citation history
-> SUBMITTED -> UNDER_REVIEW
   -> UPHELD                              (terminal, no reopen)
   -> OVERTURNED
      -> old alert rescinded, not deleted
      -> final_decision changed
      -> automatic precedent REVOKED
      -> APPEAL_OVERTURN precedent ACTIVE
      -> APPEAL_CONFIRMED training labels
      -> affected citation case list
```

本阶段不实现 M6 replay/regression、静态 HTML 报告或最终 demo 站点；不调用真实 embedding、
告警通道或训练服务。默认路径继续使用有界 fake、无网络、无 GPU、无真实人员图像。

## 冻结与 authority 规则

- 复用现有 `Precedent`、`ScoredPrecedent`、`AlertDecision`、`Appeal`、`TrainingLabel`、
  `DatasetArtifact` 和 `Case` 快照，不修改它们的既有字段、schema 或 computed identity。
- 新增 M5 wrapper，绑定 run、manifest、Case revision、Verdict、L5 review、policy、lease/attempt、
  source checkpoint、citation 或 human reviewer authority；SQLite 仍是唯一业务真相。
- 旧 verdict、alert、precedent、appeal version 和 label 均 append-only。撤销通过新状态或
  rescission authority 表达，不物理删除，也不反向改写历史 Case。
- `CLOSED` 与 `alert_outbox` 写入必须在同一 `BEGIN IMMEDIATE` 事务中完成；任何一侧失败整体回滚。
- dispatcher 至少一次执行；每个通道的 idempotency key 必须严格等于 `alert_id`。成功 receipt
  不可替换，失败 attempt 可形成后继并重试。
- 申诉终态不可重开。特殊复议只能建立新的人工案件，不复用原 appeal identity。

## 判例与精确检索

- 只检索相同 `EvidenceClass`、相同 `rule_version`、`ACTIVE` 且未失效/撤销的判例；
  `PROVISIONAL` 仅在显式离线实验查询中可见。
- 第一阶段上限小于 10,000 条，使用受控 fake embedding 与精确 cosine；所有向量必须定长、
  finite、非零，输入数量和维度有硬上限。
- 文本/视觉通道缺失时只对现有通道重新归一，不把缺失通道当零分；最终分数乘
  `source_weight`，稳定排序键为 `(-score, precedent_id)`。
- 自动判例先为 `PROVISIONAL`；到达配置冷静期且不存在有效申诉后才能转 `ACTIVE`。
- 相反方向且相似度达到阈值时进入冲突治理：高优先来源使低优先方 `INVALIDATED`；同优先级
  双方均为 `CONFLICT` 并从检索排除。
- 冲突治理必须先对完整 ACTIVE 快照计算全部有效相反方向边，再一次决定每个节点的后继，
  禁止按 pair 边读写。节点若存在更高优先级邻居则 `INVALIDATED`；否则若存在同级邻居则
  `CONFLICT`；否则保持 `ACTIVE`。`invalidated_by` 按邻居优先级降序、`precedent_id` 升序选择，
  因而混合高/同级边与输入排列均不改变结果。
- 完整 candidate authority IDs、policy/config、全部有效边和每个节点结果写入内容寻址的
  conflict batch authority/receipt；所有 current-head CAS、successor 和两项 batch root 必须在同一
  `BEGIN IMMEDIATE` 事务提交，任一失败整体回滚。
- 冲突命令的 `--limit` 是完整 active 快照预算，不是前缀批大小；候选总数超出预算时必须
  类型化失败且不写入任何冲突结果，防止固定前缀让尾部判例永久饥饿。
- 自动判例留下 durable `ACTIVATION/APPEAL_PRESENT` 收据后，同一 exact authority 不再重复进入
  激活候选；若 authority 因独立 append-only 事件产生新 revision，则必须对新 authority 重新评估。
- 撤销返回所有历史 citation case ID；旧案件保留当时 citation，不被自动改写。

## 告警、冷却与 outbox

- 只有最新 Verdict 已通过 L5 且 Case 为 `READY_FOR_ALERT_POLICY` 才能形成结案 intent。
- `NOT_ESTABLISHED` 不发送成立告警；`INSUFFICIENT_EVIDENCE` 最高 `ADVISORY`；低于 confirmed
  置信阈值不得生成 `CONFIRMED`。
- 冷却键为同 tracker epoch 内的 `(zone_id, violation_type, track_ref)`，只按帧号比较。
  配置秒数必须在已知有理数 fps 下确定性换算为帧阈值。
- 第一阶段不把匿名 track 跨 epoch/跨日拼成同一主体；无可信采集日期与稳定工位/授权主体时，
  `repeat_window_days` 不启用。
- 案件外的认证硬安全信号可建立独立 emergency outbox，但后续补审必须复用同一 `alert_id`，
  不得重复发送。

## 申诉与训练标签

- 有效状态机为 `NONE(absent) -> SUBMITTED -> UNDER_REVIEW -> UPHELD | OVERTURNED`。
- 只允许对 `CLOSED` 且有最终判决的案件提交一次有效申诉；reviewer、resolution 和 terminal
  decision 必须由显式人工命令提供。
- `OVERTURNED` 的所有副作用必须在一个 SQLite 事务中提交：保留并撤销旧 alert、更新
  `final_decision`、撤销旧自动判例、新建 active `APPEAL_OVERTURN` 判例、写入受影响 citation
  清单和 human-authored `APPEAL_CONFIRMED` labels。
- 机器弱标签永远不是 ground truth。默认 COCO 导出只包含 `HUMAN_CONFIRMED` 与
  `APPEAL_CONFIRMED`；其他质量进入隔离计数，不进入训练 artifact。
- 导出包含用途、保留期、rule version、detector manifest 与内容哈希；不复制未授权媒体。
- 每个训练标签必须与同一事务中的 `TRAINING_LABEL_APPENDED` 因果事件一一对应；数据集登记
  固定标签账本 cut、标签/Crop inventory root、精确 Case revision 与 EvidencePack 文档哈希，并以
  紧邻 cut 的登记事件封口。
- 旧数据集回放验证完整当前账本，但只使用登记 cut 以内的历史标签与 Crop authority。cut 后合法
  标签或后续 Case revision 不得改写过去登记的有效性；缺失/伪造前缀、历史文档或物理 PNG 仍
  必须 fail closed。完整决策见 ADR 0018。

## 必测场景

- 单通道与双通道 cosine、通道缺失重归一、source weight、稳定 tie-break、数量/维度/NaN 拒绝。
- rule/evidence/status 隔离，PROVISIONAL 默认不可见，冷静期前后与并发申诉竞态。
- 高优先冲突、同级冲突、revocation citation 返回及旧案不改写。
- L5 未通过不建 outbox；insufficient ceiling；帧冷却边界；跨 tracker epoch 不合并。
- Case close/outbox fault injection 全回滚；dispatcher crash/retry 不产生第二个成功 delivery。
- appeal duplicate、非法状态跳转、terminal reopen、跨 Case/verdict/reviewer authority 均 fail closed。
- overturn fault injection 在 alert、precedent、label、citation、Case 任一边界整体回滚并幂等重放。
- 默认训练导出排除 weak/consensus-only label，COCO identity 和排序可复现。
- 数据集登记遗漏 cut 前标签必须失败；cut 后合法尾标签不得改变旧报告、文件或登记状态；缺失事件、
  孤儿事件、伪造快照根、伪造历史 EvidencePack、丢失物理文件均须产生类型化失败。
