# LabCourt 技术规格

化学实验室违规行为智能仲裁系统 · 完整设计

---

## 摘要

LabCourt 把每一个疑似违规当作一桩**案件**来审理,而非"检测到即告警"。计算机视觉层持续触发候选;轻量视觉语言模型(VLM)做初审;疑难案件交由检察官、辩护人、法官三个 VLM 角色控辩会审;裁决须遵循历史判例或显式说明本案区别;判决书经确定性程序审查后方可告警;被告警人可申诉,人工改判反哺为最高优先级判例,并同时成为感知模型的训练语料。

**每一条告警都是一份可解释、可申诉、可审计的判决书。** 系统随使用同时在两条轴上变准:裁决尺度(判例)与感知精度(检测器反哺),二者皆无需推倒重训,且每次升级前经回归门禁约束尺度不漂移。

本文是自足规格:实现以数据契约(schemas / interfaces / config)为唯一真实来源。凡涉及性能数字者,须以真实部署数据验证后方可写入验收结论(见第 17 章)。

# Part I · 设计基础

## 1. 问题与定位

实验室监控系统最常见的死法不是漏报,而是**误报太多被用户关掉**。三个根因:

- **误报导致弃用**:反光、遮挡、动作歧义都会让单帧阈值告警误触发,用户失去信任后直接关停。
- **黑箱执法引发抵触**:告警无依据、无解释,"凭什么让 AI 判我违规"是这类系统推行失败的真正阻力。
- **判决漂移且无法场景自适应**:同场景今天报明天不报;严格的药化实验室与宽松的教学实验室需要不同尺度,传统方案只能靠重训或调阈值。

市面产品(通用安监、PPE 检测)停留在"单帧检测 + 阈值告警";"VLM 复核"开始普及但均为单模型一次性看图。**对抗式多智能体裁决 + 判例机制**在安防场景是空白。

LabCourt 的定位由此确定:不做更准的检测器,而做一套**把主观语义判断、客观可验证性质、政策执行三者分离**的裁决系统——语义判断归 VLM,客观量归确定性代码,政策归规则引擎。检测层的不完美由下游多级裁决消化;裁决的可信由确定性守门保证;裁决的一致与自适应由判例保证;落地阻力由"执法标准始终由本实验室安全员定义,AI 只是执行者"化解。

## 2. 设计公理

以下五条是不可破坏的约束,系统的其余部分都是它们的推论。任何改动若与之冲突,改动错。

**公理一 · 安全底线不依赖智能层。** 明火、烟雾、无人值守加热的告警由确定性规则发出,先于任何 VLM 调用,且在 VLM / 网络 / 检测器全故障时仍然工作。智能层只能在此之上**增加**能力,永不能成为安全底线的唯一依据。

**公理二 · AI 提议,代码守门。** 主观语义(这张脸戴没戴护目镜、这个动作是不是倾倒)由 VLM 判断;客观可验证性质(这两帧是不是同一个人、这段时长多少、这个区域几个人、引用的证据是否真实存在)由确定性代码判断。判决书必须通过确定性程序审查才能触发告警。

**公理三 · 确定性可复现。** 同一视频重跑,逐案判决一致。帧号是权威时间基准,系统不读墙钟。任何 prompt、模型、规则、检测器权重、检索权重的升级,发布前须全量回放判例库,判决翻转率超阈值不得发布。

**公理四 · 证据与判据分级。** 每一层只做它有资格做的判断:边缘层出结构化事件而非告警;初审只做快速分流;会审只处理疑难;程序审查只判"合规"不判"正确";实质对错的最终裁量权归人类申诉。

**公理五 · 数据最小化。** 违规主体用匿名跟踪 ID 关联工位/门禁,不做人脸识别;云端仲裁仅上传相关裁切;人脸打码在像素落盘的唯一出口执行;系统输出为安全提醒与记录,不直接作为处罚依据。

## 3. 两个核心区分

整个系统架在两个概念区分上。理解它们,架构的形状就是自明的。

### 3.1 存在型违规 vs 缺失型违规

违规分两个**证据类**,归类决定其整条确证路径:

- **存在型(presence)**:检测到某物或某行为**存在**即违规。证据是空间的、**可证实的**——把区域放大看,要么有敞口试剂瓶要么没有。例:试剂敞口、拉窗超限、实验室饮食、明火。
- **缺失型(absence)**:检测到某物**缺失**才违规。证据是时序的、**只能证伪的**——"检测器没报告护目镜"不是证据,因为它可能是没戴,也可能是没认出来。证伪缺失的反例存在于**时间窗**内,而非单帧的分辨率里。例:未戴护目镜、手套、实验服。

**为什么这个区分是承重的**:一条为"确证存在"设计的流水线(检测→裁切→放大看→确证)对存在型是健全的,但用它处理缺失型是范畴错误。一个人戴着护目镜、低头调仪器、护目镜被角度和刘海遮住半秒——检测器漏检、裁下这半秒、放大看这半秒的脸,四步会**基于同一个坏瞬间一致地错**。缺失型需要的是时序上的证据搜索(这个人在这段时间里,是否在任何清晰帧被确证戴着?),不是空间上的分辨率放大。系统为缺失型单设**窗口确证**路径(第 8.6 节),这是它与所有"单帧 + VLM 复核"方案的根本分野。

### 3.2 预防 vs 问责

系统的第一目的是安全,不是取证。因此拆成两条互不阻塞的路径:

- **预防路径**:实时、确定性、无记忆、无惩罚意味、零 VLM。人将被灼伤之前提醒他戴护目镜——价值高于事后一张可申诉的罚单。大量违规在此路径被化解(人戴上了,根本不产生案件)。
- **问责路径**:事后、审判式、可申诉、可审计。仅处理未被预防化解的、已发生的违规。

这个拆分的红利不止于功能:它让监控的姿态从"抓你"变成"帮你",由架构而非话术兑现落地叙事。

# Part II · 架构

## 4. 分层总览

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 预防路径(实时 · 无记录 · 零 VLM)                                       │
│  L0 预防     进入高危区 PPE 缺失 → 即时软提醒(屏/声光),不建案         │
├─────────────────────────────────────────────────────────────────────────┤
│ 编排        案件生命周期 · 降级 · 积压补审                               │
├─────────────────────────────────────────────────────────────────────────┤
│ 问责路径 · 感知与证据                                                     │
│  L1 感知     开放词表检测 + 跟踪 + 姿态 → 否定关联 → 缺失型窗口确证       │
│  L2 证据     时间预切割 + 空间三级裁切 + 缺失型时序裁切                   │
│ 问责路径 · 裁决                                                           │
│  L3 初审     单 VLM 判断 + 分歧驱动级联                                   │
│  L4 会审     检察官 / 辩护人 / 法官 + 判例注入 + 主动取证                 │
│  L5 守门     程序审查(六项确定性校验)+ 发回重审 + 告警策略             │
│ 记忆与自进化                                                             │
│  L6 判例     检索(文本+视觉)/ 冲突治理 / 版本失效 / 撤销溯源            │
│     申诉     受理 / 裁定 / 人工改判反哺                                   │
│     反哺     漏检与改判样本 → 检测器 LoRA 微调 → 回归门禁 → 灰度         │
├─────────────────────────────────────────────────────────────────────────┤
│ 能力        检测器 · VLM 客户端 · 嵌入器(文本/视觉)· 仿真 · 评测 · 回归 │
├─────────────────────────────────────────────────────────────────────────┤
│ 契约(全系统唯一数据与接口来源)                                         │
│  schemas · interfaces · config · prompts · manifest · labels             │
└─────────────────────────────────────────────────────────────────────────┘
```

**依赖规则**:感知/裁决/能力层只依赖契约层,互相之间不直接引用,由编排层组装。需要新字段先改契约。这保证每一层可独立测试、独立替换。

**统一输入契约**:六层管线只认一份输入——`(FrameRef, list[Detection])` 流。谁产出这份契约(仿真世界、视频文件适配器、未来的 RTSP 适配器),L0 及以上完全无感。这是仿真与真实像素能共用同一套触发与裁决逻辑的原因。

## 5. 主数据流

```
帧源 (FrameRef, [Detection])
  → L0 旁路:实时软提醒(不进以下流程)
  → L1 触发引擎
       ├─ 硬规则事件 ⇒ 立即发紧急告警(先于一切 VLM)
       ├─ 存在型 ⇒ 状态机计时达阈 → 候选事件
       └─ 缺失型 ⇒ 否定关联 + 窗口确证 → 候选事件
  → L2 证据包
       ├─ 通用:±N 秒事件片段抽帧 + 全景/主体/焦点三级裁切 + 传感元数据
       └─ 缺失型:沿轨迹按可观测性选 M 帧清晰头部 → 时序裁切
  → L3 初审(轻量 VLM)
       ├─ 高置信 ⇒ 快审结案(约 90% 事件)
       └─ 灰区/冲突 ⇒ 升级会审
  → L4 控辩会审(仅疑难)
       检索判例 → 检察官举证 → 辩护人反证 → 法官裁决或取证(≤2 轮)
  → L5 程序审查(纯确定性,六项)
       ├─ 驳回 ⇒ 发回重审(≤2 次;仍不过 ⇒ 转人工)
       └─ 通过 → 告警策略引擎(分级/冷却/累犯)→ 告警发出
  → 判决入判例库(含"不成立")
  → [异步] 漏检/改判样本入训练缓冲区,喂检测器反哺
```

## 6. 数据契约(核心工件)

### 6.1 证据类与违规类型

```
证据类 EvidenceClass:
  PRESENCE   存在即违规 · 可证实 · 空间证据
  ABSENCE    缺失才违规 · 只可证伪 · 时序证据

违规类型 ViolationType(每类静态绑定一个证据类):
  护目镜缺失 / 手套缺失 / 实验服缺失          → ABSENCE
  试剂敞口 / 实验室饮食 / 单人危险操作 / 拉窗超限 → PRESENCE
  加热无人值守 / 烟雾异常                       → PRESENCE(硬规则)
```

违规类型与证据类的绑定是静态的,新增任何违规类型时,第一个必须回答的问题就是"它是存在型还是缺失型"——答案决定它走哪条确证路径。这个约束被抬到类型系统里,而非藏在代码分支中。

### 6.2 核心数据模型

| 模型 | 含义 | 关键字段 |
|---|---|---|
| `FrameRef` | 帧引用 | `frame_id = "{相机}_{帧号}"`(帧号权威),`ts`(帧号与 fps 推导),`camera_id` |
| `Detection` | 单检测 | 类别(含开放词表类)、bbox、置信度、跟踪 ID、姿态关键点 |
| `CandidateEvent` | 候选违规事件 | 违规类型、证据类、区域、时间窗、涉事/相关轨迹、是否硬规则、L1 置信度、窗口确证记录 |
| `Crop` | 单裁切 | 来源(全景/主体/检测框焦点/锚区焦点/重裁切)、帧引用、bbox、路径、可观测性 |
| `EvidencePack` | 案件证据包 | 关键帧、三级裁切、时序裁切(仅缺失型)、L1 传感元数据(时长/人数/区域基准);内建引用闭包自检 |
| `ScreeningResult` | 初审结论 | 决定(不成立/成立/升级)、违规概率、逐帧判定(缺失型)、理由 |
| `Verdict` | **判决书** | 结论(成立/不成立/证据不足)、置信度、论述、证据引用、控辩双方论证、法官对辩方逐条回应、判例引用(遵循/区别)、取证日志、可量化断言、程序审查结果、观测充分性证据(缺失型) |
| `Case` | 案件全生命周期 | 事件、初审、判决(含被驳回历史版)、终局结论、告警、申诉、时间线、token 用量 |
| `Precedent` | 判例 | 情境文本(检索键)、视觉向量、裁决方向、来源(自动/预置/申诉改判)、状态(生效/冲突/失效/撤销)、规章版本、证据类 |
| `AlertDecision` | 告警决定 | 等级(建议/确定/紧急)、通知对象、命中规则、冷却抑制标记 |
| `ProceduralDefect` | 程序缺陷 | 缺陷码(14 种)、详情 |
| `TrainingLabel` | 反哺样本 | 裁切路径、区域框、标签、来源(漏检回收/申诉确认)、案件 ID、规章版本 |

# Part III · 感知与证据

## 7. L0 预防层

问责路径之外的旁路,复用感知层的实时检测输出,零 VLM、零建案、零记录、不可申诉。它服务的是"预防优先于问责"——在人被灼伤之前提醒他,而不是事后记一笔账。

运作逻辑:

```
对每一帧的每条人体轨迹 P:
  z = P 脚点所在区域
  若 z.风险等级 ≥ 高 且 z 要求护目镜:
      若 not goggles_present(当前帧, P):          # 复用第 8.3 节的关联判断
          若 现在 − 上次提醒[P.跟踪ID] > 提醒冷却:  # 默认 30 秒
              发出软提醒(z.显示端, "请佩戴护目镜")   # 屏幕/声光
              上次提醒[P.跟踪ID] = 现在
```

三个设计要点:

- **无状态机计时**:预防不等驻留阈值,进区即时提醒。这是它与问责路径的分工——预防求"早",问责求"准"(问责要等驻留阈值以过滤瞬时误触发)。
- **无记忆**:去抖表仅在内存,进程重启即忘;不写任何持久文件,不产生任何可追溯记录。
- **削减下游负载**:人被提醒后戴上,问责路径的缺失计时被重置,不产生候选事件。**预防在源头削减问责流水线,且削减的正是"提醒即改正"的良性案件**——监控由此从"抓你"变为"帮你"。

成本近乎为零,不新增任何模型调用。

## 8. L1 感知层

持续运行,毫秒级。产出结构化事件流(非告警)。本层承担全系统最脆弱的判断——从像素里认出物体、区分"没戴"与"没认出"——因此它的设计围绕一条原则:**把不可靠的判断降解为可靠的判断**。

### 8.1 模型选型

| 组件 | 选型 | 理由 |
|---|---|---|
| 检测器 | **YOLO-World(开放词表)** | 把 CLIP 文本嵌入融进 YOLO 检测头:用文本提示即可召回护目镜、手套、实验服、瓶盖、拉窗等通用数据集没有的类别,**同时输出边界框、保持实时速度、可接跟踪**。这是"用语义触发"的正确形态——纯 CLIP 只给全图相似度分,没有定位,下游无法裁切 |
| 跟踪 | **ByteTrack** | 关联式跟踪,无需重识别网络(轻量),对低置信检测鲁棒(恰好匹配开放词表放开阈值后的低置信框);产出跟踪 ID 作为**确定性身份锚**——身份连续性由此归代码,不归 VLM |
| 姿态 | **RTMPose(轻量)** | 产出头部关键点(鼻/眼/耳)与手腕关键点,用于在检测器沉默时仍能定位关键区——这是缺失型焦点裁切的前提 |

三者经统一检测器接口抽象,权重与提示词是版本化工件。部署时应对当期最新权重重新评估,接口不变。

### 8.2 开放词表提示词

检测提示词是版本化工件,纳入回归门禁——它的改动和 prompt、规则一样可能改变判决。

```
person         → "person"
goggles        → "safety goggles, protective eyewear"
gloves         → "latex gloves, nitrile gloves on hands"
lab_coat       → "white lab coat"
reagent_bottle → "laboratory reagent bottle, chemical bottle"
bottle_cap     → "bottle cap, bottle lid"
fume_sash      → "fume hood sash window"
food           → "food, drink cup, snack"
```

计数、时长、身份全部依赖 person 跟踪,而 person 是检测器的强项。因此下游确定性守门(第 12 章的客观量核对)所依赖的地面真值**未被开放词表的噪声污染**——噪声只进入了"触发",没进入"计数"。

### 8.3 否定判断代码化

**原则**:某物在不在关键区,是检测(归模型);"缺失即违规"这个否定推断,归确定性代码。绝不向模型提示"没戴护目镜的人"——否定式语义模型不可靠。

判断"某人当前帧是否佩戴护目镜"的算法:

```
goggles_present(帧 f, 轨迹 P):
  1. 关键区推导 anchor(P, f):
       姿态可用 → 由头部关键点(鼻/双眼/双耳,置信≥阈)外接框加上下边距
       否则回退 → 由人体框上部推导头部框
  2. 关联:
       对每个护目镜检测 det:
         若 det.置信 ≥ τ_g 且 IoU(det.bbox, anchor) ≥ τ_iou:
           返回 True
       返回 False
```

默认 `τ_g = 0.35`、`τ_iou = 0.15`(关键区框小,重叠阈放宽)。手套/实验服同构,关键区换手腕/躯干。**存在归模型,关联逻辑归代码**——否定这一脆弱环节被挡在模型之外。

### 8.4 可观测性:用于选帧,不用于门控

开放词表检测器的"漏检"与"物体真不在"在像素上完全一样。因此"缺失"只有在系统**本有公平机会看清**时才算证据。一个直觉的做法是用可观测性做**触发门控**——看不清就不触发。**这个做法有害,必须避免。**

原因:低可观测(背身、运动模糊、阴影)与真违规**正相关**。规范操作者通常正面、稳态、光照好;图省事不戴护目镜快速倒试剂者,更可能背身、匆忙、在角落。门控会**系统性地在与危害相关的维度上偏置召回**,优先漏掉最该抓的违规,而且指标上("误报率"很漂亮)看不出来——这是把系统的盲区与它的危害区对齐。

**正确用法**:可观测性不决定是否触发,只在证据层决定**看哪几帧**(把最清晰的头部送 VLM)。看不清的缺失型候选照样进入流程,靠窗口确证(8.6)与观测充分性校验(12.2 第六项)兜底,而非在源头被丢弃。

可观测性分 `obs(f, P) ∈ [0,1]`,加权归一:

```
obs = w1·人体检测置信
    + w2·头部关键点可见比例
    + w3·正面度(由眼距/脸宽或偏航角估计)
    + w4·清晰度(头部裁切的拉普拉斯方差归一,测模糊)
    + w5·曝光正常(头部裁切直方图非过曝/欠曝)
    + w6·(1 − 遮挡比例)
默认权重 (0.15, 0.25, 0.20, 0.20, 0.10, 0.10),需在开发集校准
```

### 8.5 存在型触发

存在型违规由确定性状态机计时触发:检测到目标(敞口瓶、越线拉窗、食物容器等)在指定区域持续超过驻留阈值即产出候选事件,附冷却去重。逻辑简单直接,因为存在型的证据本就是可证实的,无需时序确证。

### 8.6 缺失型窗口确证(本系统的签名机制)

缺失型违规的判定单位**不是触发瞬间,而是轨迹时间窗**。核心判别信号是**检测恢复**。

**信号的逻辑**:若一个人真戴着护目镜,跨越一段时间窗,检测器会**偶发成功**——在角度好转、运动停顿的某些帧上,护目镜会跳进检测,即便多数帧失败。若一个人真没戴,检测器**从不恢复**,因为没有东西可检。所以判别问题不是"当前区间清不清晰"(那会退回门控),而是"在缺失区间及其后续窗口内,检测器是否曾恢复过一次置信检出"。

**这个信号不重蹈危害对齐**:即便背身匆忙者,只要戴着,总会在某帧(角度好转时)触发一次检出;真没戴者给再多机会也零检出。时间窗给了检测器多次机会,而机会的多寡与观测质量无关。

算法:

```
L1 每条人体轨迹维护缺失计时器:采样帧 goggles_present=0 则累加,=1 则清零。
累计达 T_absence(按区风险 5–15 秒)时,先确证再决定是否产出:

confirm_absence(P, t_start, t_now):
    # t_start 为缺失区间起点,t_now 为达到阈值的时刻
    look = [t_start, min(t_now + W_lookahead, 轨迹终点)]   # W_lookahead 默认 10 秒
    恢复 = 存在某帧 f ∈ look 使得 goggles_present(f,P) 且 检出置信 ≥ τ_high
    若 恢复:
        # 缺失区间起点之后检测器恢复了正检 ⇒ 全程实际戴着,缺口是漏检
        返回 抑制                # 假阳死在源头,连证据包都不建
    否则:
        # look 窗内从不恢复 ⇒ 真没戴 或 中途摘下(摘下亦属违规)
        返回 产出候选事件
```

**三情形正确性**(这是算法的验收依据):

| 情形 | 检测器行为 | 恢复 | 结果 | 正确性 |
|---|---|---|---|---|
| 戴着但瞬时漏检(刘海/角度) | 缺失区间起点后某帧恢复检出 | 是 | 抑制 | ✓ 假阳死在源头 |
| 中途摘下 | 摘下前有检出,摘下后窗内不再恢复 | 否 | 产出 | ✓ 摘下确属违规 |
| 全程未戴 | 从不检出 | 否 | 产出 | ✓ 真违规 |
| 系统性漏检(此人/角度/款式检测器根本认不出,虽戴着) | 窗内亦不恢复 | 否 | 产出(误) | 残留假阳 → 下游 VLM 多半能看出并驳回 → 残差喂反哺回路,精度随时间收敛 |

**关键设计点**:确证看的是"缺失区间**起点之后**是否恢复",而非整条轨迹历史。这正确区分了"摘下"(前有检出、后无恢复 → 产出)与"漏检"(区间内或后恢复 → 抑制),避免用摘下前的检出把真违规压掉这一陷阱。确证记录(检查帧、是否恢复、恢复帧号)随候选事件下传,供证据层复用清晰帧、供守门层审计。

### 8.7 硬规则:降级底线

明火与烟雾由纯计算机视觉帧差检测,**绝不涉及机器学习**,是绝对底线。无人值守加热不依赖识别加热设备——把加热工位登记为固定区域,退化为确定性规则:该区域有活动信号且人数为零持续 N 分钟。硬规则命中立即发紧急告警,先于一切 VLM,不进级联。**开放词表检测器永远只是候选路径的增项,从不是安全底线的唯一依据。**

### 8.8 放开阈值旋钮与其代价

压漏检的旋钮是放开检测置信阈或缩短驻留时间,让更多候选进来,靠初审便宜地杀假阳。**代价不落在本层,落在初审层**:候选量上涨意味着初审 VLM 调用数上涨,这是边缘算力问题而非云端账单问题——一个更好的失败模式,但必须实测候选率与初审吞吐后再定阈值(第 18 章)。窗口确证在此的作用是把遮挡型假阳拦在证据层之前,不让它们消耗初审;它缓解"假阳导致的算力浪费",但不消除"提高真实召回本身要付的算力"。

## 9. L2 证据层

亚秒级,事件触发。产出标准化证据包。原则:**裁切与全景必须并存**——纯裁切丢上下文会造成新误判,而监控广角下护目镜只占几十像素,不裁又不可靠。

### 9.1 时间预切割

```
事件片段:[t_trigger − N_前, t_trigger + N_后],默认 ±15 秒
关键帧:触发帧 + 状态突变帧(缺失计时越阈帧 / 进区帧 / 拉窗越线帧)+ 片段首尾对照帧
```

### 9.2 空间三级裁切

| 级别 | 内容 | 来源 | 分辨率 |
|---|---|---|---|
| 全景 | 降采样全帧(长边 768px) | 全景 | 降采样,保留场景上下文 |
| 主体 | 涉事人员全身,框外扩 15% | 检测/跟踪框 | 原始 |
| 焦点 | 违规判定关键区放大 | 见下 | 原始/上采样 |

**焦点裁切按证据类分派**:

- **存在型** → 检测框驱动:裁那个具体物体(瓶口、拉窗标线区)。检测器此刻有框可用。
- **缺失型** → 几何关键区驱动:检测器正沉默、无框可裁,故围绕头部/手腕关键区裁高分辨率的脸/手,让 VLM 自己判有没有护目镜。

裁切继承 L1 的检测与关联误差,法官"重裁切"取证(11.4)保留为纠错通道。

### 9.3 缺失型时序裁切

既然缺失型的判定单位是时间窗,证据包必须支撑窗口级判断:

```
在窗口确证的 look 窗内,取可观测性最高的 M 帧(默认 M=3):
  对每帧裁头部关键区,标注来源为锚区焦点,附该帧可观测性与跟踪 ID
  存入证据包的时序裁切集
```

下游 VLM 由此拿到"这个人这段时间里的几张最清晰的脸",判断地基从**一帧的脆值**变为**窗口的稳值**。这也是可观测性的正解落地:它只影响送哪几帧,不影响是否立案。

### 9.4 隐私与成本

若仲裁走云端,默认仅上传裁切(焦点/主体),无关人员不出镜;全景仅上传文字描述,完整帧像素仅限本地模型。人脸打码在裁切落盘的唯一出口插入。时序裁切使图像 token 从"一张脸"变"M 张脸",线性增加,可控;M 是稳健性与成本的旋钮。

# Part IV · 裁决

裁决路径的设计目标是**在成本可控下把误报杀干净,并让每一步都可解释、可审计**。三层级联:大多数事件在初审便宜地结案,只有疑难进会审,所有告警前过确定性守门。

## 10. L3 初审层

秒级,事件触发。它是分歧驱动级联的成本闸门,也是系统正确率的咽喉——因为窗口确证已在感知层拦掉大部分假阳,进到初审的多是真候选,而初审之后只有灰区案件能得到会审的兜底。

### 10.1 模型选型

本地轻量 VLM,推荐 **Qwen2.5-VL-7B**(单卡 4090)。理由:强视觉语言能力、本地可跑、契合成本模型。经 VLM 客户端接口抽象,可替换为同级模型。

### 10.2 角色定位与提示词

初审是开放词表放开阈值那一波假阳的**主力灭火器**。提示词的关键是**显式点破缺失型的混淆,不让 VLM 继承感知层的缺失偏向**:

```
[缺失型提示词要点]
"以下是同一人在一段时间内的若干清晰面部图。上游检测器可能漏掉了护目镜,
 请仅凭图像逐张判断该人此刻是否佩戴护目镜,不要预设'检测器说没有就是没有'。
 对每张图输出:已戴 / 未戴 / 看不清,并给出理由。"
```

### 10.3 级联路由与缺失型聚合

**存在型**(阈值快审):

```
违规概率 ≤ 0.15  ⇒ 快审:不成立
违规概率 ≥ 0.88  ⇒ 快审:成立
0.15 < 概率 < 0.88 ⇒ 升级会审
```

**缺失型**(先逐帧,再聚合):

```
对时序裁切逐帧判 已戴/未戴/看不清
清晰帧 = 判定非"看不清"的帧
  清晰帧数 < K                       ⇒ 会审前补证门(不调用控辩裁)
  存在任一"已戴"清晰帧               ⇒ 快审:不成立(存在清晰"戴着"帧 = 观测缺口)
  全部清晰帧"未戴" 且 清晰帧数 ≥ K   ⇒ 快审:成立(K 默认 2)
  证据充分但语义不一致             ⇒ 升级会审
```

**会审前补证门**:客观观测不足不是控辩双方能通过更多文字解决的语义争议。当 `clear_count < K`
时,系统先检查当前不可变 run source 是否能产生新的合法清晰证据;只有新证据能形成完整的
successor EvidencePack 时才允许重跑一次 L3。当事件区间的 top-M 已经穷尽、工具不可用或补证后仍不足
时,转人工复核,不创建会审 session,也不从观测不足推导违规成立。

**冲突升级**:感知层强信号与初审结论冲突,无条件升级会审。缺失型的判据从单帧变多帧,快审仍便宜(看 M 张脸,token 略增),但地基更稳。

## 11. L4 会审层

数十秒级,仅疑难案件(灰区或冲突)。这是系统与所有"单模型一次看图"方案拉开差距的地方——用对抗把单一模型的偏向暴露出来。

### 11.1 模型选型与角色异构

检察官、辩护人、法官三角色,可用本地 **Qwen2.5-VL-72B**(2×A6000)或云端 API,可混合。**角色异构增强对抗多样性**:不同模型担任不同角色,减少同源偏向。云端角色不上传完整帧像素(隐私红线)。

### 11.2 控辩审流程

```
检察官:论证违规成立,标注证据帧(论点 + 证据引用)
辩护人:寻找反证——反光 / 遮挡 / 角度 / 动作歧义
        [缺失型专轴] "感知层的'缺失'可能是漏检而非真缺失;开放词表置信偏低;
                      时序裁切中是否存在被忽略的'戴着'帧"
法官:综合双方 + 判例 → 裁决 或 申请取证
      - 逐条回应辩方每条反证(守门层强制校验)
      - 遵循判例,或显式说明本案区别对待(理由非空)
```

**缺失型在会审的定位被有意调低**:其主要纠错已前移到感知层的窗口确证——更靠前、更确定、更便宜。会审主要给存在型歧义(反光/遮挡/角度)和真正疑难案件兜底。这是一个刻意的分工:缺失型是可证伪不可证实的违规,证伪它该是一次确定性的窗口查询,不该是会审里的举证表演。

### 11.3 主动取证

法官证据不足时可申请(≤2 轮):

| 取证动作 | 用途 |
|---|---|
| 争议时刻 ±30 秒补充帧 | 时序上下文 |
| 争议区域重新裁切 | 纠正证据层预切割/关键区之误 |
| 其他机位同时刻画面 | 破单机位遮挡 |
| 跟踪轨迹与置信度曲线 | 客观运动与检测证据 |

### 11.4 重裁切重检

一个专门根治漏检假阳的取证动作:**重裁切后,在高分辨率裁切上重跑开放词表检测器**。小目标在广角帧漏检、在放大裁切上却可靠——感知层那个导致假候选的漏检,能在会审被从根上治好。这把"重裁切"从"再看一眼"升级为"再看一眼且以正确分辨率重检"。检测器经取证工具接口供法官调用。

取证成功与“找到违规”必须分开:重检返回空集合是合法的工具结果,不是证明未戴;单机位无法取得同时刻其他画面时必须返回明确不可用。冻结合同无法表达的空检测和完整逐帧曲线,由版本化的 M8 增量权威保留;不得伪造哨兵 Detection 或把帧号塞入自由文本。

### 11.5 证据质量、违规风险与语义裁决分离

- 证据质量只描述像素是否给予公平判断机会,不是违规概率。
- 违规风险概率只能由本地真实人工标注集上的可复现检测/时序特征训练并校准;不得使用 L3/L4 自报概率或 confidence 作为特征。
- L3/L4 负责语义解释和结构化裁决,不产生统计概率。
- 校准未通过封存集验收前只能以 `SHADOW` 记录,不得改变 M3/M4/L5/告警路由。UI 必须把模型自报分数标记为“未校准、不参与概率评估”。

## 12. L5 守门层

毫秒级,**纯确定性代码,零 token**。判决书生成后、告警执行前的守门人。

### 12.1 边界

L5 只判"判决是否**合规**",**不判"判决是否正确"**——实质对错归 VLM 与人类申诉。**切勿把实质判断写成规则**,否则退化为传统规则引擎的误报地狱。因此 L5 不提高单案正确率,它提高的是**可审计性与幻觉拦截率**:一个"看清了、判对了流程、结论却错"的判决,L5 照样放行。它守的是链路可信,不是结论正确。

### 12.2 六项确定性校验

| # | 校验 | 拦截的缺陷 |
|---|---|---|
| 1 | **结构合规**:JSON Schema、枚举值、必填字段 | 结构畸形、非法枚举、缺字段 |
| 2 | **证据落地**:引用的证据帧/裁切真实存在于本案证据包,标注框坐标合法 | 伪造证据引用、非法坐标 |
| 3 | **判例引用校验**:判例 ID 存在于库且相似度达标;声明"遵循"则裁决方向须一致,声明"区别对待"则理由非空 | 伪造判例、方向不符、区别理由为空 |
| 4 | **逻辑一致性**:成立判决须有 ≥1 证据帧与非空控方论证;辩方每条反证法官须回应;置信度与告警等级匹配(低置信不得出"确定级") | 成立无证据、反证未回应、置信等级错配 |
| 5 | **客观事实核对**:判决中的可量化断言(时长/人数/区域)与感知层传感数据比对,矛盾即驳回——**主观判断归 VLM,客观量以跟踪器为准** | 可量化断言矛盾、违规类型不符 |
| 6 | **缺失型观测充分性**:缺失型成立判决,证据包须含 ≥K 张达标清晰帧且一致指向"未戴";若包内实际存在一张清晰"戴着"帧却判成立,或清晰帧数不足,则不合规 | 从观测不足推出缺失 |

**第六项的意义**:防"从没看清推出缺失"。若脸从未看清却判"确认未戴护目镜",这是逻辑不成立。**它不牺牲召回**:案件不在感知层被丢(窗口确证照样立案),只是阻止一个观测不足下的高置信有罪判决——可降级为"建议级"提醒而非"确定级"告警,既防过度指控又保留召回。第五、第六项用的都是可靠的那半边(人体跟踪),因此开放词表的噪声未削弱守门层的地面真值地位。

### 12.3 发回重审

```
通过 ⇒ 交告警策略引擎
驳回 ⇒ 发回重审:附具体缺陷清单,重审次数 +1
        次数 ≤ 2 ⇒ 回会审重审(带缺陷提示)
        次数 > 2 ⇒ 转人工
```

被驳回的判决版本入案件历史,可审计。发回重审率与重审修复成功率是量化的幻觉评测指标。

### 12.4 告警策略引擎

```
等级 = 策略表[(违规类型, 置信区间, 区域风险等级, 是否累犯)]  → 建议 / 确定 / 紧急
通知对象 = 路由表[等级, 区域]
去重合并:同(区域, 违规类型, 轨迹)在冷却窗内合并
```

**候选量上来后,冷却/去重窗口是保住"每路每日误报次数"指标不爆的关键闸门,不得放松。** 累犯窗口:同轨迹/工位在窗口内(默认 7 天)复现升级等级。

# Part V · 记忆与自进化

这是系统区别于一次性检测器的核心:它有记忆,并随使用在两条轴上变准——**裁决尺度**(判例)与**感知精度**(反哺)——二者皆无需推倒重训,且每次变化都经回归门禁约束不漂移。三者(判例、申诉、反哺)共用同一份数据资产。

## 13. L6 判例库

### 13.1 检索:文本 + 视觉融合

| 通道 | 模型 | 说明 |
|---|---|---|
| 文本 | **BGE-M3**(中文强) | 情境文本(违规类型 + 区域 + 关键属性)向量化 |
| 视觉 | **CLIP ViT-L/14** | 焦点裁切向量化——"像上次那个护目镜推额头的案子"可视觉召回,不只靠文字 |

```
分数(查询, 判例) = α·文本余弦 + β·视觉余弦,再乘来源权重(申诉改判 1.25 / 预置 1.0 / 自动 1.0)
按证据类过滤同类;取 top-k(默认 4)注入法官上下文
默认 α=0.7, β=0.3,融合权重需在开发集调初值
```

α、β 纳入回归门禁——检索变则判决可能翻转。视觉通道是 CLIP 的正确归宿:相似度检索是它的强项,触发/检测是它的短板(不出框、否定语义弱)。

### 13.2 判例治理(防自我污染)

- **冲突检测**:新判例入库时与同违规类型的生效判例比相似度;方向相反且相似度 ≥ 0.55 则冲突。按来源优先级(申诉 > 预置 > 自动)自动裁决,低优先方失效;同级则双方标冲突,交管理员指定主导判例(界面一键)。
- **规章版本化**:规章升级时旧版本判例整体标"依据已变更",停止被引用。
- **撤销溯源**:撤销判例时返回全部曾引用它的案件清单,可定位受影响案件。
- **冷启动**:上线前由安全员对 50–100 个历史片段做预判例导入。

## 14. 申诉闭环

人类判例反哺,是"执法标准由本实验室安全员定义"的机制兑现。

```
被告警人提交申诉(仅已结案且有判决;状态机 未申诉→已提交,终态不可重开)
  → 管理员裁定
      ├─ 维持 ⇒ 归档
      └─ 改判 ⇒ 改写终局结论;
                本案自动判例显式废止;
                生成申诉改判判例入库(检索加权 1.25,最高优先)
```

涌现效应:人工推翻一个"其实是漏检"的误判,该判例下次被检索(现可视觉召回)时直接帮到辩方;而它同时成为下一节的检测器训练样本。

## 15. 检测器反哺回路

系统每天在产生一件极有价值的数据:每个"感知层沉默但终局判定戴着"的案件,是检测器的一个**已标注漏检样本**;每个申诉改判,是一个**人类确认的困难样本**。这是全自动产生、带地面真值、本实验室专属的训练数据流。不利用它,检测器永远停在零样本,系统"越用越准"的只有裁决尺度,感知能力一天不变——而漏检恰是感知层全部麻烦的源头。

回路机制:

```
① 标签采集(结案时异步):
   感知层沉默 且 终局=不成立(戴着) ⇒ 训练样本(来源=漏检回收,
       裁切取时序裁切中被 VLM 判"戴着"的帧,区域取关键区,标签=护目镜存在)
   申诉改判 ⇒ 训练样本(来源=申诉确认,人工确认标签)
   检测器命中 且 确认无护目镜 ⇒ 真负例(用于校准)
   写入训练缓冲区

② 触发再训练(周期性,每 N 个标签或每周):
   对开放词表检测器的本地类(护目镜/手套/实验服/瓶盖/拉窗)做 LoRA 微调
   —— 零样本文本提示起步(立即补冷启动词表缺口),再从积累数据渐进微调

③ 门禁(强制):
   新检测器权重 → 全量重放判例库回归 → 判决翻转率 < 阈值(5%)
   → 翻转案例逐条人工复核 → 灰度上线 → 监控 → 全量

④ 版本化:检测器权重与检测提示词作为工件固定,纳入回归门禁
```

**结构性收益**:把"开放词表检测器对本实验室护目镜零样本精度未知"这个风险,从**静态风险**变成**随使用收敛的量**——零样本不够不致命,只要回路转起来,精度是时间的函数而非祈祷的对象。迁移路径由此闭合:零样本上线,用判例数据越练越准。这也是数据护城河真正咬合处:不止护住裁决尺度,更护住感知能力。

## 16. 回归门禁

判例库的第三重身份(前两重是检索键与训练语料):**版本管理的回归测试集**。

任何 prompt、模型、规则、检测器权重、检索权重的升级,发布前全量重放已结案件(机器判决对机器判决;申诉改判案件单列,不参与门禁):

```
翻转率 = 判决方向改变的案件数 / 重放案件数
翻转率 > 5% ⇒ 不得发布;翻转案例逐条人工复核后方可发布
```

价值:模型与检测器的迭代不再凭感觉,执法尺度的稳定性可量化。这是公理三("确定性可复现")在工程上的落点——系统可以进化,但进化必须是**受控的、可回滚的、尺度不漂移的**。

# Part VI · 工程

## 17. 评测体系与数据集

没有评测协议,"误报率下降 50%"就只是口号。本章是验收与实验的共同基础。

### 17.1 数据集构建

无公开的化学实验室违规数据集,自建三源:

1. **摆拍采集**:演员按脚本演绎正例与**难负例**——反光、遮挡、**护目镜推额头**(缺失型关键难例)、拿水杯对比拿试剂瓶。每类不少于 100 段。
2. **真实回放**:上线后真实触发事件经人工标注持续入池。
3. **合成增强**:透明玻璃器皿等难检目标的合成数据(器皿贴 ArUco 码兜底)。

标注规范:违规类型 + 证据类 + 时间区间 + 关键对象框 + **缺失型专项:窗口内每帧已戴/未戴/看不清** + 仲裁级标签。争议样本双人标注,分歧仲裁。划分为开发集(调 prompt/阈值/权重)与**封存测试集**(仅验收时运行,防过拟合)。

### 17.2 指标体系

| 维度 | 指标 |
|---|---|
| 检出 | 各类漏报率;**每路每日误报次数**(直接对应"会不会被用户关掉") |
| 裁决质量 | 会审相对初审误报下降率;与安全员盲判一致率(Cohen's κ) |
| 一致性 | 同案重放裁决一致率;相似案件裁决一致率(判例机制的直接检验) |
| 幻觉 | 伪造引用率、发回重审率、重审修复成功率 |
| 缺失型专项 | 窗口确证三情形分类准确率(漏检/摘下/未戴);清晰帧不足案件占比;观测充分性驳回率 |
| 反哺专项 | 检测器护目镜召回随再训练轮次的曲线;每轮回归翻转率 |
| 性能与成本 | 各层延迟;单事件平均 token 成本;进初审候选率;灰区升级比例;初审边缘吞吐 |
| 消融 | 纯感知 → 单 VLM → 控辩会审 → 加判例库 → 加窗口确证 → 加反哺,逐级对比 |

## 18. 验证计划与开放问题

一份诚实的设计文档必须区分"已推理论证"与"须经验验证"。本系统的架构性质(降级、守门、可复现、机制正确性)可由设计保证;但**凡涉及性能数字的断言,均依赖本实验室真实数据,验收前不得当作既成结论**。下列问题是上线前的必测项,也是"能否谈保证"的前提。

| 问题 | 决定什么 | 测量方法 |
|---|---|---|
| 开放词表检测器对**本实验室护目镜**的零样本清晰帧召回 | 感知层低漏检成不成立;窗口确证"系统性漏检"情形多不多 | 封存集上量清晰正面帧的护目镜召回 |
| 放开阈值后**进初审候选率**与**初审边缘吞吐** | 4090 扛不扛得住;检测阈值定多松 | 真实视频跑一段,量候选率与 7B 实际吞吐 |
| **窗口确证的地基假设**:缺失型假阳的缺失区间内,检测器是否曾恢复正检 | 窗口确证救不救得动;救不动则须动镜位 | 标注一批缺失型假阳,量"窗内存在恢复正检"的比例 |
| 初审 VLM 在**放大脸判 PPE**的准确率 | 系统正确率咽喉 | 开发集上量逐帧已戴/未戴准确率 |
| 可观测性权重与清晰度下限 | 选帧质量;第六项校验松紧 | 开发集扫参 |
| 会审相对初审的实际下降幅度 | 验收指标达不达得到 | 封存集消融 |

> 第三项是全套缺失型机制的地基:若坏瞬间前后窗口**同样看不清**(工位长期背对主机位),窗口查询无帧可查——**任何软件层到头,须加一个正对主操作区的机位根治**。因此落地第一步是量这一项,再决定"动算法还是动镜位"。

### 成本的真实耦合(避免误解为可同时全降)

准确率、成本、算力三者不是可一并达成的一揽子:

- **准确率与算力对立**:压漏检等于放开触发,候选量涨,初审调用涨,边缘算力涨。窗口确证只缓解"假阳浪费",不消除"提高真实召回本身的算力"。
- **云端成本与边缘算力此消彼长**:会审放本地则云端省、边缘涨;放云端则反之。总负载不因架构漂亮而凭空减少,只在两账本间移动。
- **唯一纯赚**:分歧级联(约九成不进会审)+ 窗口确证(遮挡假阳不进初审)+ 冷却去重——砍掉的是本不该发生的计算。

诚实结论:本架构能在"消除假阳浪费"范围内同时拿到准确率与低成本;越过此范围,提准确率必付算力或云端的账,无同时全降的方案。

## 19. 部署、硬件、成本、降级

### 19.1 硬件与成本量级(一期)

| 项目 | 选型 | 量级 |
|---|---|---|
| 摄像头 | POE 枪机/半球 2–4 路 | 0.3–1.5k 元/路 |

### 19.2 延迟目标

| 环节 | 目标 |
|---|---|
| L0 软提醒 / 硬规则告警 | <1 秒 |
| 缺失型窗口确证(纯代码) | <100 毫秒 |
| 初审 | <10 秒 |
| 会审(含主动取证) | <90 秒 |
| 程序审查 | <100 毫秒 |

### 19.3 降级与补审

任何 VLM 阶段不可用时,案件转人工、事件追加进积压队列;硬规则告警不受影响(已在 VLM 之前发出)。恢复后按事件 ID 复用原案件(不重复建案)、不重发硬告警、补审完成后积压文件轮转归档。**安全底线的可用性与智能层完全解耦**——这是公理一的运行时体现。

## 20. 边界、伦理、合规

- **明示监控**:区域公示 + 人员知情同意;数据最小化(无关人员打码、本地优先、云端仅裁切)。
- **不做人脸识别**:违规主体用匿名跟踪 ID 关联工位/门禁,告警仍可送达本人申诉。规避合规负担,同时保留问责能力。
- **不作处罚依据**:系统输出为安全提醒与记录,涉及处分必须人工复核——既是伦理要求,也是落地阻力最小化策略。L0 预防层进一步把大量违规化解在"提醒"而非"记录",强化这一姿态。
- **不替代既有责任**:系统为辅助手段,不替代不免除既有巡检与安全管理责任;落地前过安全管理与伦理审批,满足《个人信息保护法》对场所监控的要求。
